# 抽取质量评估

不做评估就调提示词，等于闭着眼睛拧旋钮。

```bash
pnpm eval:extract
```

把 `eval/golden/*.md` 逐份喂给 Pass 2，与同名的 `.json` 对照，输出报告到
`eval/report-{时间戳}.md`。

## 四项指标

| 指标 | 算法 | 门槛 |
|---|---|---|
| 幻觉率 | 抽出的 metrics 里，数值在原文中找不到的条数 ÷ 总条数 | **必须 0** |
| 漏抽率 | golden 有而抽取结果没有的 metrics + actions ÷ golden 总条数 | < 20% |
| kind 准确率 | metrics 的 outcome / output 判对的比例 | > 90% |
| 切分一致性 | project / capability_slice 层级与 golden 一致的比例 | > 80% |

幻觉检测很粗糙：把 `from_value` `to_value` `delta` 里的数字抠出来，回原文做
字符串查找，找不到就判为幻觉。粗糙，但对「凭空造数字」这个最危险的失败模式
极其有效。

`kind` 准确率单列，因为它直接决定证明度对不对，是本产品的命门。

## 黄金对照集怎么建

一个案例两个文件，同名不同后缀：

- `NN.md` —— 从 `00_主档案库_v5.md` 里截出的原文段落，一段一条经历
- `NN.json` —— 这段原文的正确抽取结果，字段与 Pass 2 的输出结构一致

**现在 `golden/` 里放的是占位案例**，来自一份合成文档，专门覆盖几个已知的
失败模式（没有数值却造数、交付物被当成果、预计值被当实测、职责被升级、
该合并的小节被拆开）。

真正的对照集应该是手工录入的那六条经历：截出对应原文存成 `01.md` ~ `06.md`，
把库里的结构导出成 `01.json` ~ `06.json`，然后把占位案例删掉。
